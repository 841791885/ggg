# PRD-001：内存版商品与 SKU 管理

## 1. 文档信息

- 所属项目：GoMall 单商户商城
- 阶段：PRD-001
- 状态：待开发
- 优先级：P0
- 目标版本：v0.1.0
- 本阶段技术：Go、Gin、内存存储、Go 标准测试工具
- 下一阶段技术：MySQL 8、`database/sql`、`go-sql-driver/mysql`、Goose

相关文档：

- [商城系统总 PRD](./PRODUCT-PRD.md)

## 2. 阶段目标

实现一个可运行、可测试、并发安全的商品目录 API。运营人员可以管理商品和 SKU，消费者只能看到允许销售的商品。

本阶段不追求数据持久化，重点验证以下能力：

1. 使用 Go 对商品和 SKU 建模。
2. 使用 Gin 设计清晰的管理端和消费者端 API。
3. 使用 handler、service、repository 分离 HTTP、业务与存储职责。
4. 使用明确的错误值表达业务失败。
5. 保证内存数据在并发访问下没有竞态。
6. 使用自动化测试固定业务规则。

## 3. 阶段边界

### 3.1 本阶段包含

- 商品创建、编辑、查询、分页列表、状态变更和删除。
- SKU 创建、编辑、查询和删除。
- 运营管理接口。
- 消费者商品列表和详情接口。
- 商品及 SKU 状态规则。

管理接口在本阶段不验证身份。这只是阶段性限制，PRD-003 会增加认证和角色权限。

## 4. 业务术语

### 4.1 商品

商品是消费者理解的销售对象，例如“Go 语言实战课程”。商品保存名称、描述和销售状态，但不直接保存成交价格和可售库存。

### 4.2 SKU

SKU 是实际销售和计库存的最小单元。例如同一课程可以有“电子版”和“纸质版”两个 SKU。每个 SKU 独立保存编码、规格、价格、库存和状态。

### 4.3 金额

所有金额使用人民币最小单位“分”的整数表示：

- `1999` 表示 `19.99` 元。
- 禁止使用 `float32` 或 `float64` 保存和计算金额。
- 接口字段明确命名为 `price_cent`，避免单位歧义。

## 5. 数据模型

### 5.1 Product

| 字段 | Go 建议类型 | JSON 字段 | 规则 |
| --- | --- | --- | --- |
| ID | `uint64` | `id` | 系统生成，大于 0，不可修改 |
| Name | `string` | `name` | 去除首尾空白后 2～100 个字符 |
| Description | `string` | `description` | 可为空，最多 2000 个字符 |
| Status | 自定义字符串类型 | `status` | `draft`、`on_sale`、`off_sale` |
| CreatedAt | `time.Time` | `created_at` | 系统生成，RFC 3339 输出 |
| UpdatedAt | `time.Time` | `updated_at` | 每次成功变更时更新 |

商品详情响应还应包含 `skus` 数组；商品列表是否返回完整 SKU 由接口契约明确规定。

### 5.2 SKU

| 字段 | Go 建议类型 | JSON 字段 | 规则 |
| --- | --- | --- | --- |
| ID | `uint64` | `id` | 系统生成，大于 0，不可修改 |
| ProductID | `uint64` | `product_id` | 必须关联存在的商品 |
| Code | `string` | `code` | 全局唯一，3～32 位 |
| Specs | `map[string]string` | `specs` | 至少 1 项，最多 5 项规格 |
| PriceCent | `int64` | `price_cent` | 大于 0 |
| Stock | `int64` | `stock` | 大于等于 0 |
| Status | 自定义字符串类型 | `status` | `active`、`inactive` |
| CreatedAt | `time.Time` | `created_at` | 系统生成，RFC 3339 输出 |
| UpdatedAt | `time.Time` | `updated_at` | 每次成功变更时更新 |

SKU 编码规则：

- 去除首尾空白后校验。
- 只能包含大写字母、数字、下划线和连字符。
- 必须以大写字母或数字开头。
- 区分输入错误，不由服务端自动转换大小写。
- 示例：`TSHIRT-BLACK-M`、`BOOK_GO_001`。

规格规则：

- key 和 value 去除首尾空白后都不能为空。
- key 最多 20 个字符，value 最多 50 个字符。
- 示例：`{"颜色":"黑色","尺码":"M"}`。

## 6. 状态规则

### 6.1 商品状态

```text
draft ──────> on_sale ──────> off_sale
                 ▲               │
                 └───────────────┘
```

允许的状态迁移：

| 当前状态 | 目标状态 | 是否允许 | 条件 |
| --- | --- | --- | --- |
| `draft` | `on_sale` | 是 | 至少存在一个 `active` SKU |
| `on_sale` | `off_sale` | 是 | 无额外条件 |
| `off_sale` | `on_sale` | 是 | 至少存在一个 `active` SKU |
| 任意状态 | 相同状态 | 否 | 返回状态未变化错误 |
| `on_sale`/`off_sale` | `draft` | 否 | 草稿状态不可恢复 |

商品创建后固定为 `draft`，客户端不能在创建请求中指定其他状态。

### 6.2 SKU 状态

- SKU 创建时默认状态为 `active`。
- `active` 与 `inactive` 可以相互切换。
- SKU 状态与库存是两个概念：库存为 0 的 SKU 仍可处于 `active`，但消费者端展示为售罄。
- 上架商品必须至少保留一个 `active` SKU。
- 若某操作会使上架商品失去最后一个 `active` SKU，则拒绝该操作。

### 6.3 删除规则

- `on_sale` 商品不能删除，必须先下架。
- 删除商品时同时删除其全部 SKU。
- 删除本阶段采用内存物理删除，PRD-002 接入 MySQL 后重新定义软删除策略。
- 上架商品的 SKU 不能删除。
- 删除不存在的商品或 SKU 返回 `404`。

## 7. API 通用约定

### 7.1 基础路径

- 运营接口：`/api/v1/admin`
- 消费者接口：`/api/v1`
- 健康检查：`/health/live`

### 7.2 Content-Type

- 有 JSON 响应体的接口返回 `application/json; charset=utf-8`。
- JSON 请求必须使用 `Content-Type: application/json`。

### 7.3 成功响应

单个资源：

```json
{
  "data": {
    "id": 1,
    "name": "Go 语言实战课程"
  }
}
```

列表资源：

```json
{
  "data": [],
  "meta": {
    "page": 1,
    "page_size": 20,
    "total": 0
  }
}
```

空列表必须返回 `[]`，不能返回 `null`。

### 7.4 错误响应

所有业务错误采用统一格式：

```json
{
  "error": {
    "code": "PRODUCT_NOT_FOUND",
    "message": "商品不存在"
  }
}
```

错误响应不能暴露 Go 类型、调用栈或内部实现细节。

### 7.5 分页规则

- `page` 默认值为 1，必须大于等于 1。
- `page_size` 默认值为 20，范围为 1～100。
- 超出范围返回 `400`，不静默修正。
- 默认按 `created_at` 从新到旧排序；时间相同时按 `id` 从大到小排序。

### 7.6 未知字段

创建和修改请求中的未知 JSON 字段必须返回 `400 INVALID_JSON`，避免客户端字段拼写错误被静默忽略。

## 8. 运营端 API

### 8.1 创建商品

`POST /api/v1/admin/products`

请求：

```json
{
  "name": "Go 语言实战课程",
  "description": "面向有编程基础的学习者"
}
```

成功：

- 返回 `201 Created`。
- 商品状态为 `draft`。
- SKU 数组为 `[]`。

### 8.2 查询商品列表

`GET /api/v1/admin/products?page=1&page_size=20&status=draft&keyword=Go`

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `page` | 否 | 页码 |
| `page_size` | 否 | 每页数量 |
| `status` | 否 | 精确过滤商品状态 |
| `keyword` | 否 | 商品名称包含匹配，去除首尾空白 |

要求：

- 管理端可以看到全部状态的商品。
- 列表项包含 SKU 数量，但不返回完整 SKU 数组。

### 8.3 查询商品详情

`GET /api/v1/admin/products/:product_id`

要求：

- 返回商品完整字段和全部 SKU。
- SKU 按创建时间从旧到新排序。

### 8.4 修改商品信息

`PATCH /api/v1/admin/products/:product_id`

请求示例：

```json
{
  "name": "Go Web 实战课程",
  "description": "使用 Gin 构建后端服务"
}
```

要求：

- 至少提供一个可修改字段。
- `null` 不表示清空字段，传入 `null` 返回参数错误。
- 本接口不能修改商品状态。
- 成功返回更新后的完整商品。

### 8.5 修改商品状态

`PUT /api/v1/admin/products/:product_id/status`

请求：

```json
{
  "status": "on_sale"
}
```

要求：

- 按第 6 节执行状态迁移校验。
- 成功返回更新后的完整商品。

### 8.6 删除商品

`DELETE /api/v1/admin/products/:product_id`

要求：

- 遵循第 6.3 节删除规则。
- 成功返回 `204 No Content`。
- `204` 响应不能有响应体。

### 8.7 创建 SKU

`POST /api/v1/admin/products/:product_id/skus`

请求：

```json
{
  "code": "GO-COURSE-ONLINE",
  "specs": {
    "版本": "电子版"
  },
  "price_cent": 9900,
  "stock": 100
}
```

要求：

- 关联商品必须存在。
- SKU code 全局唯一。
- 状态默认是 `active`，请求不能指定状态。
- 成功返回 `201 Created` 和 SKU 数据。

### 8.8 修改 SKU

`PATCH /api/v1/admin/products/:product_id/skus/:sku_id`

允许修改：

- `specs`
- `price_cent`
- `stock`
- `status`

要求：

- 至少提供一个字段。
- SKU code 创建后不可修改。
- SKU 必须属于路径中的商品，否则按不存在处理。
- 修改状态时遵循第 6.2 节规则。
- 成功返回更新后的 SKU。

### 8.9 删除 SKU

`DELETE /api/v1/admin/products/:product_id/skus/:sku_id`

要求：

- SKU 必须属于路径中的商品。
- 遵循第 6.3 节删除规则。
- 成功返回 `204 No Content`。

## 9. 消费者端 API

### 9.1 查询在售商品列表

`GET /api/v1/products?page=1&page_size=20&keyword=Go`

要求：

- 只返回状态为 `on_sale` 的商品。
- 只统计并返回 `active` SKU。
- 列表项包含最低价格 `min_price_cent`。
- 没有 active SKU 的商品不会出现在列表中。
- 支持按商品名称进行包含匹配。

### 9.2 查询在售商品详情

`GET /api/v1/products/:product_id`

要求：

- 只有 `on_sale` 商品可以被查询。
- 只返回 `active` SKU。
- SKU 库存可以返回，但消费者不能通过任何接口修改。
- 草稿、下架和不存在的商品均返回 `404 PRODUCT_NOT_FOUND`，不能借此探测后台数据。

## 10. 健康检查

`GET /health/live`

成功响应：

```json
{
  "status": "ok"
}
```

要求：

- 返回 `200 OK`。
- 不检查 MySQL 或 Redis，因为本阶段没有外部依赖。
- 不返回版本、路径等不必要的内部信息。

## 11. 错误码

| HTTP 状态 | 错误码 | 场景 |
| --- | --- | --- |
| 400 | `INVALID_JSON` | JSON 格式错误、未知字段或类型错误 |
| 400 | `INVALID_ARGUMENT` | 路径、分页或查询参数不合法 |
| 400 | `VALIDATION_FAILED` | 字段未满足业务校验规则 |
| 404 | `PRODUCT_NOT_FOUND` | 商品不存在或消费者不可见 |
| 404 | `SKU_NOT_FOUND` | SKU 不存在或不属于指定商品 |
| 409 | `SKU_CODE_CONFLICT` | SKU code 已存在 |
| 409 | `INVALID_PRODUCT_STATUS_TRANSITION` | 商品状态迁移非法 |
| 409 | `ACTIVE_SKU_REQUIRED` | 上架商品没有 active SKU |
| 409 | `PRODUCT_ON_SALE` | 尝试删除在售商品或其 SKU |
| 409 | `PRODUCT_STATUS_UNCHANGED` | 目标状态与当前状态相同 |
| 500 | `INTERNAL_ERROR` | 未预期的服务内部错误 |

同一业务错误在不同接口中必须保持相同错误码和 HTTP 状态。

## 12. 工程设计约束

### 12.1 目录建议

第一阶段建议形成以下目录，不需要创建后续阶段的空模块：

```text
.
├── cmd
│   └── api
│       └── main.go
├── internal
│   ├── catalog
│   │   ├── handler.go
│   │   ├── model.go
│   │   ├── repository.go
│   │   ├── memory_repository.go
│   │   └── service.go
│   └── platform
│       └── httpserver
│           └── router.go
├── docs
├── go.mod
└── go.sum
```

测试文件放在被测试代码附近。允许根据实现调整文件粒度，但不能把所有逻辑继续堆在 `main.go`。

### 12.2 职责边界

- handler：解析路径、查询和 JSON，请求 service，并转换为 HTTP 响应。
- service：执行校验、状态迁移、消费者可见性和业务流程。
- repository：保存数据并保证原子读写，不依赖 Gin。
- model：表达领域对象，不包含 HTTP 请求上下文。
- router：注册路由和通用中间件。
- main：组装依赖、启动和关闭服务。

### 12.3 依赖规则

- handler 可以依赖 service 接口或具体服务。
- service 依赖 repository 接口。
- 内存 repository 实现该接口。
- repository 不能反向依赖 handler 或 Gin。
- 不使用包级可变 map、计数器或 service 单例。

### 12.4 并发规则

- 内存 repository 使用 `sync.RWMutex` 或等效机制保护全部共享状态。
- 生成 ID、检查 SKU code 唯一和写入数据必须处于正确的原子操作边界。
- repository 返回数据副本，不能让调用者绕过锁直接修改内部 map/slice/specs。
- 测试必须覆盖并发创建、读取和修改。

### 12.5 错误规则

- 使用稳定的领域错误值或错误类型表达可预期失败。
- 使用 `errors.Is`/`errors.As` 判断包装后的错误。
- handler 不能通过比较错误文本决定 HTTP 状态。
- 未预期错误记录服务端日志，对客户端统一返回 `INTERNAL_ERROR`。

### 12.6 服务启动与关闭

- 不能忽略 `http.Server.ListenAndServe` 返回的错误。
- 使用显式 `http.Server`，不直接依赖 `router.Run()` 完成最终启动。
- 响应 `SIGINT`/`SIGTERM` 并调用 `Shutdown` 优雅关闭。
- 监听地址通过环境变量配置，默认 `:8080`。

## 13. 测试要求

### 13.1 Service 单元测试

至少覆盖：

1. 创建商品后状态为 `draft`。
2. 名称过短、过长或仅包含空白时失败。
3. 创建合法 SKU 成功。
4. SKU code 重复时失败。
5. 没有 active SKU 的商品不能上架。
6. 商品可以上架、下架和重新上架。
7. 非法状态迁移失败。
8. 上架商品不能删除。
9. 上架商品不能删除 SKU。
10. 消费者只能查询上架商品和 active SKU。

### 13.2 Repository 单元测试

至少覆盖：

1. 创建后可以按 ID 查询。
2. 更新不存在的资源返回未找到错误。
3. 删除商品同时删除 SKU。
4. repository 返回副本，外部修改不会改变内部数据。
5. 并发读写不会丢失数据或触发竞态。

### 13.3 HTTP 测试

使用 `httptest` 至少覆盖：

1. 创建商品返回 `201` 和正确响应结构。
2. 非法 JSON 和未知字段返回 `400 INVALID_JSON`。
3. 列表空数据返回 `[]` 和正确分页信息。
4. 非法分页参数返回 `400`。
5. 删除成功返回无响应体的 `204`。
6. 消费者查询草稿或下架商品返回 `404`。
7. 业务错误可以稳定映射为约定 HTTP 状态和错误码。

### 13.4 必须执行

```bash
go fmt ./...
go vet ./...
go test ./...
go test -race ./...
```

## 14. 推荐开发顺序

这不是代码答案，而是建议的实施顺序：

1. 定义 Product、SKU、状态常量和领域错误。
2. 定义 repository 行为并完成并发安全的内存实现。
3. 为 repository 编写测试，验证数据副本和竞态边界。
4. 实现 service 的创建、校验和状态规则。
5. 为 service 编写表驱动测试。
6. 实现管理端 handler 和路由。
7. 实现消费者端查询规则。
8. 增加统一错误映射、日志和健康检查。
9. 增加 HTTP 测试与优雅关闭。
10. 执行完整质量命令并按验收清单手工验证。

不要先写所有 handler 再补业务层；优先让领域规则在不启动 HTTP 服务的情况下可测试。

## 15. 验收场景

### 场景 A：商品从草稿到上架

1. 创建商品，得到 `draft` 商品和空 SKU 列表。
2. 直接上架，返回 `409 ACTIVE_SKU_REQUIRED`。
3. 创建一个 active SKU。
4. 再次上架，成功变为 `on_sale`。
5. 消费者列表和详情都能看到该商品。

### 场景 B：消费者数据隔离

1. 创建草稿商品及 SKU。
2. 管理端可以查询商品详情。
3. 消费者端查询相同商品返回 `404`。
4. 上架后消费者可见。
5. 下架后消费者再次查询返回 `404`。

### 场景 C：SKU 约束

1. 为商品创建 SKU `BOOK_GO_001`。
2. 为另一个商品创建相同 code，返回 `409 SKU_CODE_CONFLICT`。
3. 创建负价格、负库存或空规格 SKU，均返回 `400`。
4. SKU code 创建后不能通过修改接口改变。

### 场景 D：删除规则

1. 草稿商品可以删除，所属 SKU 同时消失。
2. 上架商品不能删除。
3. 下架商品可以删除。
