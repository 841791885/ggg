# GoMall 初学者术语表

这份文档用于解释 PRD 和代码中出现的商城、后端、数据库及部署术语。第一次阅读项目时先看“当前阶段必须理解”，后续术语等进入对应阶段再学习。

遇到文档中的陌生词时，先在本文件搜索。如果术语没有解释，应先补充解释再编码，不要求依靠猜测实现需求。

## 1. 当前阶段必须理解

### 1.1 商品（Product）

商品是消费者眼中的一个完整商品页面，例如：

- “GoMall Logo T 恤”
- “Go 语言商城实战电子书”
- “iPhone 15”

商品保存多个规格共同的信息，例如名称、介绍和上架状态。商品本身不一定能直接购买，因为消费者可能还需要选择颜色、尺码或容量。

数据库中的 `products` 表保存商品。

### 1.2 SKU

SKU 是 Stock Keeping Unit 的缩写，可以理解为“消费者最终选中的那个具体规格”。

假设商城有一个商品“GoMall Logo T 恤”，它可以包含这些 SKU：

| SKU 编码 | 颜色 | 尺码 | 价格 | 库存 |
| --- | --- | --- | ---: | ---: |
| `TSHIRT-BLACK-M` | 黑色 | M | 59.00 元 | 12 |
| `TSHIRT-BLACK-L` | 黑色 | L | 59.00 元 | 4 |
| `TSHIRT-WHITE-M` | 白色 | M | 69.00 元 | 0 |

这三行属于同一个商品，但它们是三个不同的 SKU。消费者购买的不是抽象的“T 恤”，而是其中一个确定的 SKU，例如“黑色、M 码”。

因此：

- 商品保存共同的名称和介绍。
- SKU 保存具体规格、价格和库存。
- 一个商品可以有多个 SKU。
- 一个 SKU 只能属于一个商品。
- 购物车和订单最终记录的是 `sku_id`，不是只有 `product_id`。
- 扣减库存时扣的是 SKU 库存。

只有一种形式的商品也需要 SKU。例如“Go 语言商城实战电子书”没有颜色和尺码，仍可创建一个编码为 `GO-BOOK-EBOOK` 的默认 SKU，用它保存价格和库存。

数据库中的 `skus` 表保存 SKU，通过 `product_id` 关联 `products` 表。

### 1.3 SKU 编码（SKU Code）

SKU 编码是运营人员使用的业务编号，例如 `TSHIRT-BLACK-M`。它与数据库自增 ID 不同：

| 字段 | 示例 | 用途 |
| --- | --- | --- |
| `id` | `18` | 数据库内部关联，系统自动生成 |
| `code` | `TSHIRT-BLACK-M` | 运营识别、导入导出和对接外部系统 |

本项目要求 SKU Code 全局唯一，即两个商品也不能使用相同编码。

### 1.4 规格（Specs）

规格描述 SKU 的具体选择，例如：

```json
{
  "颜色": "黑色",
  "尺码": "M"
}
```

本项目第一阶段使用 `map[string]string` 表达规格，并以 MySQL JSON 字段保存。后续如果需要复杂的规格筛选，再评估拆分成独立表。

### 1.5 价格（Price）

不同 SKU 可以有不同价格。代码和接口使用整数“分”保存金额：

```text
5900 分 = 59.00 元
```

不能用 `float32` 或 `float64` 保存金额，因为二进制浮点数可能产生精度误差。

### 1.6 库存（Stock）

库存表示某个 SKU 还能销售多少件。黑色 M 码和黑色 L 码分别计库存，不能只给整个商品保存一个库存数字。

第一阶段只维护基础库存数量；第五阶段才实现下单时的库存预占、防超卖和并发控制。

### 1.7 商品状态和 SKU 状态

商品状态决定整个商品页面是否对消费者可见：

- `draft`：草稿，运营人员编辑中。
- `on_sale`：已上架，消费者可以查看。
- `off_sale`：已下架，消费者不可查看。

SKU 状态决定某个具体规格是否可售：

- `active`：启用。
- `inactive`：停用。

`active` 不等于有库存。一个 SKU 可以处于启用状态但库存为 0，此时页面显示“售罄”。

### 1.8 第一阶段实际操作流程

第一阶段完成后的操作顺序是：

1. 创建商品“GoMall Logo T 恤”，商品初始状态为 `draft`。
2. 给商品创建 SKU“黑色 M 码”，设置价格 5900 分、库存 12。
3. 再创建 SKU“黑色 L 码”，设置价格 5900 分、库存 4。
4. 将商品从 `draft` 改为 `on_sale`。
5. 消费者查询商品详情，看到两个可选择的 SKU。
6. 修改某个 SKU 的价格或库存，不影响其他 SKU。

当前代码已完成第 1～3 步需要的数据库模型和 Repository，Service 与 HTTP API 仍在开发中。

## 2. Go 后端分层术语

| 术语 | 通俗解释 | 在本项目中的位置 |
| --- | --- | --- |
| Route（路由） | 决定某个 URL 交给哪个处理函数 | `routes/` |
| Controller | 接收 HTTP 请求、解析参数并返回 JSON | `controllers/` |
| Request DTO | 只描述某个接口允许客户端提交的字段 | 后续的 `controllers/product_request.go` |
| Response DTO | 只描述某个接口承诺返回的字段 | 后续的 `controllers/product_response.go` |
| Model | 表达商品、SKU 等领域对象及数据库映射 | `models/` |
| Service | 执行业务校验和流程，例如“没有有效 SKU 不能上架” | `services/` |
| Repository | 隔离数据库操作，提供创建、查询、更新和删除能力 | `repositories/` |
| Middleware（中间件） | 在请求进入 Controller 前统一处理日志、认证等逻辑 | 由 `routes/` 注册 |
| Dependency Injection（依赖注入） | 在 `main.go` 创建依赖并传给下一层，而不是使用全局变量 | `main.go` |

一次商品请求的调用方向：

```text
浏览器
  -> Route 找到接口
  -> Controller 解析 JSON
  -> Service 判断业务是否允许
  -> Repository 操作数据库
  -> Controller 返回 Response JSON
```

## 3. 数据库术语

| 术语 | 通俗解释 |
| --- | --- |
| Database（数据库） | 一组相关表的集合，本项目开发库叫 `gomall` |
| Table（表） | 保存同类数据的结构，例如 `products` |
| Row（行） | 一条具体数据，例如一个商品 |
| Primary Key（主键） | 唯一标识一行数据，本项目通常是 `id` |
| Foreign Key（外键） | 保证关联对象存在，例如 `skus.product_id` 指向商品 |
| Unique Index（唯一索引） | 保证某个值不能重复，例如 SKU Code |
| Index（索引） | 帮助数据库更快定位数据，但会增加写入和存储成本 |
| Transaction（事务） | 多个数据库操作要么全部成功，要么全部失败 |
| Row Lock（行锁） | 临时锁住正在修改的数据，避免并发操作互相破坏 |
| Soft Delete（软删除） | 不真正删除行，只填写 `deleted_at`，普通查询不再返回它 |
| Migration（迁移） | 按版本保存并执行建表、加字段等结构变化的 SQL |
| ORM | 将 Go 结构体与数据库表进行映射的工具 |
| GORM | 本项目使用的 Go ORM |
| DSN | 包含数据库地址、账号、库名和参数的连接字符串 |
| Connection Pool（连接池） | 复用一定数量的数据库连接，避免每个请求重新连接 |
