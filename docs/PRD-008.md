# PRD-008：可靠异步任务、超时关单与通知

## 1. 阶段信息

- 状态：预规划
- 前置条件：PRD-007 验收通过
- 核心技术：goroutine、channel、context、MySQL Outbox、任务重试、优雅停机
- 阶段目标：把非即时工作移出请求链路，同时保证进程重启和多实例环境下任务不会丢失或重复产生业务副作用。

## 2. 功能范围

- 待支付订单到期后自动取消并释放库存。
- 支付成功、订单取消和后续发货事件生成站内通知。
- 业务事务通过 Outbox 写入待处理事件。
- 后台 worker 领取、执行、重试和完成任务。
- 失败任务按指数退避进行有限重试。
- 超过重试上限的任务进入失败状态供运营查看和重放。
- 多实例竞争时同一任务只被一个 worker 同时处理。
- 服务优雅停机，停止领取新任务并等待正在执行的任务结束。

## 3. 数据变化

新增：

- `outbox_events`：事件类型、聚合 ID、payload、状态、下次执行时间、尝试次数和锁定信息。
- `notifications`：用户、类型、标题、内容、已读状态、业务关联和时间戳。

事件状态：

```text
pending -> processing -> succeeded
                    └-> retry_wait -> processing
                    └-> failed
```

payload 必须有 schema/version 字段，避免未来结构变化无法兼容旧任务。

## 4. 技术设计

- 业务数据和 Outbox 事件在同一 MySQL 事务内写入。
- worker 从 MySQL 可靠领取任务，可使用 `FOR UPDATE SKIP LOCKED` 或等效安全方案。
- channel 只用于进程内 worker 调度和背压，不作为可靠消息存储。
- 每类 handler 必须幂等，以业务唯一键或状态条件避免重复副作用。
- worker 数量、轮询间隔、批量大小、执行超时和重试上限均可配置。
- Redis 可以用于快速唤醒或协调，但 MySQL 任务表仍是事实来源。

## 5. API 增量

消费者：

```text
GET /api/v1/notifications
PUT /api/v1/notifications/:id/read
PUT /api/v1/notifications/read-all
```

运营端：

```text
GET  /api/v1/admin/tasks
POST /api/v1/admin/tasks/:id/retry
```

运营重试必须记录操作者，且只允许重试处于 failed 的任务。

## 6. 核心规则

- 订单创建时记录到期时间，不依赖进程内定时器。
- 关单任务执行时重新检查订单状态；已支付订单不能取消。
- 关单、释放库存和状态日志必须处于同一事务。
- 相同订单重复执行关单只有一次业务效果。
- 通知失败不能回滚已成功的支付或订单事务。
- 任务异常必须被捕获并记录，不能导致整个 worker 池崩溃。
- 服务关闭超过等待时间后取消剩余任务并保留可恢复状态。

## 7. 实施步骤

1. 设计事件类型、payload 版本和任务状态机。
2. 创建 Outbox 与通知迁移。
3. 在订单创建、支付和取消事务中写入事件。
4. 实现安全领取、心跳/超时恢复和状态更新。
5. 实现有界 worker pool、context 取消和 panic 防护。
6. 实现超时关单 handler。
7. 实现站内通知 handler 和查询接口。
8. 实现重试、退避、失败任务和人工重放。
9. 将 worker 生命周期接入服务优雅停机。
10. 运行多实例竞争、进程中断和恢复测试。

## 8. 测试要求

- 业务事务回滚时不会留下孤立 Outbox 事件。
- 服务重启后 pending/retry_wait 任务继续执行。
- 两个 worker 实例不能同时产生重复副作用。
- 关单与支付并发时最终状态符合事务先后，不出现负库存。
- handler 失败按策略重试，超过上限进入 failed。
- 人工重放只能针对允许状态且保留审计记录。
- 优雅停机不领取新任务，已领取任务受控结束。
- `go test -race` 不报告 channel、worker 或关闭流程竞态。

## 9. 验收标准

- 未支付订单按配置时间自动取消并准确释放库存。
- 已支付订单不会被延迟关单任务取消。
- 关键业务事件能生成通知，通知故障不阻塞交易。
- 任务在重启和多实例环境下可恢复、可追踪。
- 可以查看失败原因并安全重试失败任务。
- goroutine 没有已知泄漏，优雅停机有效。

## 10. 本阶段不做

- 不引入 Kafka、RabbitMQ 或独立任务平台。
- 不发送真实短信和邮件。
- 不拆分 worker 微服务，先与 API 使用同一代码库和可配置进程模式。

## 11. 阶段出口

系统已经具备可靠副作用处理机制，可以承载优惠券返还、退款和更多交易事件。
