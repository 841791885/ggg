# PRD-009：优惠券、发货、退款与评价

## 1. 阶段信息

- 状态：部分完成（券模板 CRUD、领取去重、退款申请与审核、评价写入/显隐已落地；优惠计算接入下单、券并发防超发、幂等发货为进阶点待补）
- 前置条件：PRD-008 验收通过
- 核心技术：规则计算、多个状态机、MySQL 事务、可靠任务、幂等退款
- 阶段目标：补齐促销、履约和售后，使消费者完成从优惠下单到评价或退款的完整交易生命周期。

## 2. 功能范围

### 优惠券

- 运营创建满减优惠券模板，配置发行量、每人限领、领取期和使用期。
- 消费者领取、查看可用/已用/过期优惠券。
- 下单预览和创建订单时选择一张优惠券。
- 服务端验证门槛并计算优惠金额。
- 订单取消时按规则返还优惠券。

### 发货与收货

- 运营为已支付订单填写模拟承运商和物流单号。
- 消费者查看物流信息并确认收货。
- 订单从待发货进入已发货，再进入已完成。

### 退款

- 消费者按订单项申请仅退款。
- 运营审核同意或拒绝。
- 通过模拟支付 Provider 执行退款。
- 保存退款金额、原因、状态和渠道退款号。
- 重复回调或重试不产生多次退款。

### 评价

- 已完成订单的购买者对订单项评分并填写文字评价。
- 同一订单项只能评价一次。
- 商品详情返回评价列表和平均评分。
- 运营可隐藏违规评价，但不能物理删除审计事实。

## 3. 数据变化

新增：

- `coupon_templates`：名称、门槛、减免、发行限制、有效时间和状态。
- `user_coupons`：用户、模板、状态、领取/使用/返还时间和关联订单。
- `shipments`：订单、承运商、物流单号、发货人与时间。
- `refunds`：退款单号、订单项、申请人、金额、状态、原因和渠道结果。
- `refund_status_logs`：退款状态历史。
- `reviews`：用户、商品、订单项、评分、内容、展示状态和时间。

## 4. 状态与金额规则

订单扩展状态：

```text
pending_payment -> pending_shipment -> shipped -> completed
       └-> cancelled
```

退款状态：

```text
requested -> approved -> refunding -> refunded
         └-> rejected
```

金额规则：

- 优惠门槛基于商品总额，具体口径在实现前固定并写入测试。
- 优惠金额不得超过商品总额，应付金额不能小于 0。
- 订单保存优惠券、优惠规则和优惠金额快照。
- 可退金额不得超过订单项实际支付分摊金额减去已退金额。
- 金额分摊必须保证各项之和严格等于订单实付金额，尾差有确定归属规则。

## 6. 核心规则

- 优惠券领取使用事务和条件更新，不能超发或超过个人限额。
- 下单创建时再次验证优惠券并原子标记占用/使用。
- 发货接口必须幂等，相同物流信息重试不产生重复记录。
- 只有订单所有者且符合状态和期限的订单项可以申请退款。
- 审核人与申请人权限分离，运营操作写入审计事件。
- 渠道退款成功回调需要幂等处理。
- 退款后的库存是否回补必须依据商品是否实际退回；本阶段“仅退款”默认不回补库存。
- 评价必须绑定真实已完成订单项，隐藏评价保留原始内容和操作记录。

## 7. 实施步骤

1. 固定优惠计算、金额分摊和返券规则。
2. 实现优惠券模板、领取和并发限量。
3. 将优惠计算接入下单预览与订单事务。
4. 扩展订单状态机并实现幂等发货、确认收货。
5. 定义退款状态机和 Payment Provider 退款接口。
6. 实现退款申请、审核、异步执行和回调。
7. 通过 Outbox 生成发货、退款通知和返券任务。
8. 实现评价写入、展示和运营隐藏。
9. 增加金额、状态、并发和权限组合测试。

## 8. 测试要求

- 优惠券并发领取不超发行量和个人上限。
- 过期、未开始、门槛不足和他人优惠券不能使用。
- 订单金额分摊在各种尾差下保持总额相等。
- 重复发货、重复确认和非法状态迁移被正确处理。
- 退款金额不能超过可退金额，重复退款无重复资金效果。
- 非购买者、未完成订单和重复评价被拒绝。
- 隐藏评价后消费者不可见但审计记录存在。

## 9. 验收标准

- 消费者能领取优惠券并正确优惠下单。
- 运营能发货，消费者能确认收货并评价。
- 消费者能申请退款，运营审核并完成模拟退款。
- 所有金额和状态变化都有快照或流水可追踪。
- 并发领取、重复回调和重复操作不破坏数据。
- 完整交易流程自动化集成测试通过。

## 10. 本阶段不做

- 不实现换货、退货物流、复杂促销叠加或跨店优惠。
- 不接真实物流和真实退款渠道。
- 不实现匿名评价和推荐算法。

## 11. 阶段出口

商城业务闭环已经完整。后续阶段不再扩张主要业务，而是集中加强安全、部署、可观测性和性能。
