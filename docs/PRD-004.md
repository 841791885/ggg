# PRD-004：收货地址与购物车

## 1. 阶段信息

- 状态：已完成（地址 CRUD + 事务默认切换、购物车增删改查/合并/选择、下单预览服务端计价；OpenAPI 契约文档待补）
- 前置条件：PRD-003 验收通过
- 核心技术：MySQL、事务、OpenAPI、所有权校验、批量查询
- 阶段目标：实现消费者的购买准备流程，并确保私有数据隔离和服务端价格可信。

## 2. 功能范围

- 收货地址新增、修改、删除、列表和默认地址设置。
- 购物车添加 SKU、修改数量、删除、选择与取消选择。
- 同一用户重复添加相同 SKU 时合并数量。
- 购物车展示商品当前名称、图片、价格、库存与有效状态。
- 商品下架、SKU 停用或库存不足时标记不可购买。
- 生成下单预览，重新读取服务端价格和库存。
- 从本阶段开始维护可供前端使用的 OpenAPI 契约。

## 3. 数据变化

新增：

- `addresses`：用户、收件人、手机号、省市区、详细地址、默认标记和时间戳。
- `cart_items`：用户、SKU、数量、是否选中和时间戳。

关键约束：

- 同一用户与 SKU 组合唯一。
- 每个用户最多保存 20 个有效地址。
- 每个用户最多 100 条购物车记录。
- 数量必须在 1～99 之间。
- 默认地址切换使用事务，保证最多一个默认地址。
- 本阶段购物车以 MySQL 为事实来源，PRD-006 再引入 Redis。

## 4. API 增量

地址：

```text
POST   /api/v1/addresses
GET    /api/v1/addresses
PATCH  /api/v1/addresses/:id
PUT    /api/v1/addresses/:id/default
DELETE /api/v1/addresses/:id
```

购物车：

```text
POST   /api/v1/cart/items
GET    /api/v1/cart
PATCH  /api/v1/cart/items/:id
DELETE /api/v1/cart/items/:id
PUT    /api/v1/cart/selection
POST   /api/v1/cart/preview
```

接口从认证上下文获取用户 ID。路径和请求体不允许指定资源所属用户。

## 5. 核心规则

- 地址属于用户私有数据，访问其他用户地址统一按不存在处理。
- 删除默认地址后不自动选择新默认地址，避免隐式业务决定。
- 创建第一个地址时自动设为默认地址。
- 购物车只表达购买意向，不锁库存、不固定价格。
- 加入购物车时校验商品与 SKU 可购买，之后状态变化通过购物车查询反映。
- 购物车接口不得信任客户端提交的价格、商品名和库存。
- 下单预览只返回实时可购买项和不可购买原因，不创建订单。
- 批量查询商品/SKU，避免逐条 N+1 数据库查询。

## 6. OpenAPI 要求

- 描述认证方式、请求字段、响应模型、错误码和分页参数。
- 示例不能包含真实密码、Cookie 或生产地址。
- 契约变更必须与实现同步。
- 前端应能依据契约生成类型或编写稳定请求层。

## 7. 实施步骤

1. 编写地址与购物车迁移。
2. 实现地址 repository/service 和所有权规则。
3. 使用事务实现默认地址切换。
4. 实现购物车写入和同 SKU 合并。
5. 设计购物车聚合查询，消除 N+1 查询。
6. 实现商品失效、价格变化和库存不足标记。
7. 实现下单预览计算。
8. 建立 OpenAPI 文档并与 HTTP 测试对齐。
9. 增加用户隔离和并发更新测试。

## 8. 测试要求

- 两个用户无法互相查询、修改或删除地址与购物车项。
- 并发设置默认地址后仍最多只有一个默认地址。
- 并发加入相同 SKU 后只有一条记录且数量正确。
- 数量边界、地址上限和购物车上限测试通过。
- 商品下架、SKU 停用、价格变化和库存不足均正确展示。
- 下单预览使用服务端实时价格，不接受篡改值。
- 对购物车列表执行查询次数检查，避免 N+1。

## 9. 验收标准

- 用户可以完整维护地址和购物车。
- 所有私有资源均按当前认证用户隔离。
- 默认地址和购物车唯一约束在并发下成立。
- 下单预览金额、商品状态和库存提示正确。
- OpenAPI 与实际接口响应一致。
- 全部自动化质量检查通过。

## 10. 本阶段不做

- 不创建订单、不锁定库存、不使用优惠券。
- 不使用 Redis 保存购物车。
- 不实现匿名购物车或跨设备离线合并。

## 11. 阶段出口

购物车与下单预览形成稳定输入。PRD-005 将把预览结果重新校验后固化为订单快照，并在数据库事务内预占库存。
