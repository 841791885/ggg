# PRD-011：Nginx、多实例与 Docker Compose

## 1. 阶段信息

- 状态：预规划
- 前置条件：PRD-010 验收通过
- 核心技术：Docker、Docker Compose、Nginx、MinIO、TLS、优雅停机
- 阶段目标：建立可重复的一键部署环境，验证 API 无状态化、多实例负载均衡和共享文件存储。

## 2. 最终容器组成

```text
nginx
api-1
api-2
worker（可与 API 使用同一镜像、不同启动命令）
mysql
redis
minio
migrate（一次性迁移任务）
```

前端构建产物由 Nginx 提供静态服务。商品图片从 PRD-002 的本地 `FileStorage` 迁移到兼容 S3 API 的 MinIO 实现，避免多个 API 实例各自保存不同文件。

## 3. 功能范围

- Go API/worker 多阶段 Docker 镜像。
- 容器以非 root 用户运行，镜像不包含编译缓存和源码冗余。
- Compose 启动 MySQL、Redis、MinIO、迁移任务、两个 API、worker 和 Nginx。
- Nginx 提供前端静态资源、API 反向代理、负载均衡和请求大小限制。
- 演示环境使用本地证书提供 HTTPS，HTTP 重定向至 HTTPS。
- API 区分 liveness 和 readiness。
- 服务接收 SIGTERM 后停止接收新请求并优雅关闭。
- worker 停止领取新任务并等待处理中任务。
- 配置通过环境变量注入，并提供 `.env.example`。

## 4. Nginx 规则

- `/api/` 代理到 Go API upstream。
- `/health/` 可按需要直接代理健康实例。
- `/assets/` 与前端入口由 Nginx 服务。
- SPA 路由回退到 `index.html`，API 404 不得回退前端页面。
- 转发并覆盖正确的 `Host`、`X-Forwarded-For`、`X-Forwarded-Proto` 和请求 ID 头。
- 设置连接、读取、写入和请求体超时/大小限制。
- upstream 只包含就绪实例，失败时进行有限重试，非幂等写请求不盲目重试。
- Nginx 可增加粗粒度边缘限流，但应用层业务限流继续保留。

## 5. 容器与配置规则

- 镜像固定基础镜像版本，不使用不可追踪的 `latest`。
- 运行镜像只包含可执行文件、CA 证书和必要时区数据。
- MySQL、Redis 和 MinIO 使用命名卷。
- API 容器不把业务状态写入本地可变文件系统。
- 密钥不写入镜像、Compose 文件和 Git。
- `.env.example` 只提供变量名和安全示例。
- 迁移由一次性任务执行，多个 API 实例不并发自动迁移。
- readiness 只有在 MySQL 可用且必要初始化完成后成功。

## 6. MinIO 迁移

- 为已有 `FileStorage` 增加 S3/MinIO 实现。
- 对象 key 由服务端生成，不直接使用原始文件名。
- bucket 默认私有，通过应用生成受控访问地址或经 Nginx 代理。
- 上传成功但数据库写入失败时执行清理或记录补偿任务。
- 删除数据库图片记录与对象清理采用可恢复策略。
- 提供从开发本地文件迁移测试数据的说明，不要求生产级批量迁移工具。

## 7. 实施步骤

1. 重构应用入口，支持 `api`、`worker`、`migrate` 运行模式。
2. 编写 Go 多阶段 Dockerfile 和非 root 运行配置。
3. 增加 MySQL、Redis、MinIO 和命名卷。
4. 增加一次性 Goose migration 服务和依赖顺序。
5. 启动两个 API 实例及独立 worker。
6. 实现 MinIO FileStorage 并迁移运行配置。
7. 编写 Nginx upstream、静态资源、代理和 TLS 配置。
8. 完善 liveness、readiness 和优雅停机。
9. 编写一键启动、初始化、停止、日志和清理说明。
10. 执行实例故障、依赖重启和持久化验证。

## 8. 测试要求

- Compose 从干净环境能够完整启动。
- 迁移任务成功后退出，失败时 API 不应假装就绪。
- 请求可命中不同 API 实例，用户和购物车状态保持一致。
- 停止任一 API 后其余实例继续服务。
- 重启 MySQL、Redis、MinIO 或 worker 后行为符合恢复策略。
- 多实例上传和读取同一商品图片结果一致。
- SIGTERM 期间已接收请求和任务受控完成。
- HTTP 正确跳转 HTTPS，API 404 不返回前端 HTML。

## 9. 验收标准

- 一条 `docker compose up` 命令可启动完整演示环境。
- Nginx 是浏览器访问系统的唯一入口。
- 至少两个 API 实例处于负载均衡后方。
- 任一 API 实例没有必须共享的本地业务状态。
- 数据和图片在容器重建后仍保留。
- 健康检查和优雅停机正确。
- 仓库不包含真实密钥和可写生产凭据。

## 10. 本阶段不做

- 不部署 Kubernetes，不配置云厂商负载均衡。
- 不购买域名或申请正式公网证书。
- 不建立 MySQL/Redis 高可用集群。
- 不把数据库或 Redis 打包进 API 镜像。

## 11. 阶段出口

系统已有可重复的多实例部署环境，为最终指标采集、压测和故障演练提供稳定基线。
