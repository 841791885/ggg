# PRD-005：订单、库存与并发控制

## 1. 阶段信息

- 状态：部分完成（订单 CRUD、幂等键创建、商品/地址快照、状态机与状态日志已落地；库存预占事务、条件原子更新防超卖、死锁重试为进阶点待补）
- 前置条件：PRD-004 验收通过
- 核心技术：MySQL InnoDB 事务、条件更新/行锁、状态机、幂等键
- 阶段目标：实现正确的下单和库存预占，保证并发场景不超卖、不重复创建订单。

## 2. 功能范围

- 从购物车选中项或指定 SKU 立即购买创建订单。
- 服务端重新计算商品金额和应付金额。
- 保存商品、SKU、价格、规格和地址快照。
- 创建订单时预占库存。
- 用户主动取消待支付订单并释放库存。
- 消费者订单列表与详情。
- 运营人员按状态、订单号、用户和时间查询订单。
- 订单状态机和状态变化历史。
- 客户端幂等键防止重复下单。
- 库存人工调整与完整库存流水。

## 3. 数据变化

新增：

- `orders`：订单号、用户、状态、金额、地址快照、幂等键和时间戳。
- `order_items`：订单、商品/SKU 标识及名称、规格、单价、数量、小计快照。
- `inventory_records`：SKU、变化量、变化后数量、类型、关联业务和操作者。
- `order_status_logs`：订单、原状态、目标状态、操作主体、原因和时间。

商品 SKU 库存模型需明确：

- `available_stock`：当前可被新订单预占的数量。
- `reserved_stock`：已被待支付订单预占的数量。
- 两者均不能为负数。

## 4. 订单状态

本阶段状态：

```text
pending_payment ──> cancelled
```

支付成功状态在 PRD-007 引入。当前只允许：

- 创建订单进入 `pending_payment`。
- 用户取消自己的 `pending_payment` 订单进入 `cancelled`。
- 相同状态重复取消返回幂等成功或固定冲突策略，阶段实现前必须统一。
- 任何接口不得任意设置订单状态字符串。

## 5. API 增量

消费者：

```text
POST /api/v1/orders
GET  /api/v1/orders
GET  /api/v1/orders/:id
POST /api/v1/orders/:id/cancel
```

管理端：

```text
GET  /api/v1/admin/orders
GET  /api/v1/admin/orders/:id
POST /api/v1/admin/skus/:id/inventory-adjustments
GET  /api/v1/admin/skus/:id/inventory-records
```

创建订单请求必须携带 `Idempotency-Key`。相同用户、相同 key 的重试返回首次创建结果；相同 key 但请求内容不同返回冲突。

## 6. 核心规则

- 金额使用“分”的 `int64`，订单总额等于订单项小计之和。
- 不接收客户端提交的订单总价、单价或用户 ID。
- 地址与商品信息保存快照，后续修改不影响历史订单。
- 创建订单、订单项、预占库存和库存流水处于同一事务。
- 预占库存使用带条件的原子更新或明确行锁，禁止先查后改的竞态写法。
- 事务内访问多个 SKU 时按稳定顺序加锁，降低死锁概率。
- 数据库发生死锁时只对确认可安全重试的事务进行有限重试。
- 取消订单、释放预占库存和状态日志处于同一事务。
- MySQL 是订单和库存的唯一事实来源。

## 7. 实施步骤

1. 设计订单状态机与库存不变量。
2. 编写订单、订单项、库存流水和状态日志迁移。
3. 实现订单编号与用户幂等键约束。
4. 实现单 SKU 库存预占事务并编写并发测试。
5. 扩展为多 SKU 固定顺序预占，处理部分失败回滚。
6. 实现订单快照、金额计算与订单创建。
7. 实现取消订单和库存释放。
8. 实现消费者与运营查询接口。
9. 实现运营库存调整和审计流水。
10. 执行并发压测，确认无超卖、无库存丢失。

## 8. 测试要求

- 订单金额、小计和数量边界使用表驱动测试。
- 商品价格变化后历史订单快照不变。
- 地址修改后历史地址快照不变。
- 相同幂等键并发请求只创建一张订单。
- 多个请求抢购有限库存时成功数量不超过库存。
- 多 SKU 中任一库存不足时整个订单事务回滚。
- 取消订单只释放一次库存。
- 不同用户不能查看或取消对方订单。
- 死锁/事务失败路径不会留下半张订单或错误库存流水。

## 9. 验收标准

- 可从购物车或立即购买创建正确订单。
- 订单快照和金额由服务端正确生成。
- 并发购买最后库存不超卖，库存不为负。
- 重复提交不会生成重复订单。
- 取消订单能原子释放库存并记录状态历史。
- 库存每次变化都有可追踪流水。
- 普通测试、集成测试、竞态检查全部通过。

## 10. 本阶段不做

- 不支付、不自动关单、不发货、不优惠。
- 不用 Redis 分布式锁代替数据库事务。
- 不拆分订单或库存微服务。

## 11. 阶段出口

订单和库存正确性已经由 MySQL 事务与约束保证。后续 Redis 只负责性能和协调，不能绕过本阶段建立的数据库不变量。
