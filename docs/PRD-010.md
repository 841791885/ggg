# PRD-010：安全、分布式限流与审计

## 1. 阶段信息

- 状态：预规划
- 前置条件：PRD-009 验收通过
- 核心技术：Redis Lua、令牌桶、Gin middleware、安全响应头、审计日志、fuzz test
- 阶段目标：保护高价值接口、收紧输入与代理信任边界，并让关键管理操作可追踪。

## 2. 功能范围

- 登录、注册、刷新令牌、下单、支付、领券和退款接口限流。
- 同时支持 IP 维度、用户维度和接口维度的策略。
- 多个 Go 实例共享一致的限流状态。
- 管理操作审计：登录安全事件、商品价格、SKU 库存、订单、发货、退款、角色和账号状态。
- 请求体大小、字符串长度、分页大小和上传大小限制。
- CORS、Cookie、CSRF 相关策略和安全响应头。
- 可信代理列表与客户端 IP 获取规则。
- 敏感配置和日志脱敏检查。

## 3. 限流技术设计

使用 Redis + Lua 实现原子令牌桶：

- Lua 脚本在一次 Redis 调用中完成补充令牌、判断、扣减和设置过期。
- key 包含环境、策略名、接口、主体类型和主体 ID/IP。
- 不直接拼入未规范化的任意用户输入。
- 每个策略配置容量、补充速率和失败行为。
- 返回 `429 Too Many Requests`、稳定错误码和 `Retry-After`。

首批策略示例，具体数值在压测阶段前可配置调整：

| 接口 | 主体 | 初始策略 |
| --- | --- | --- |
| 登录 | IP + 账号摘要 | 低速率，防暴力尝试 |
| 注册 | IP | 低速率 |
| 下单 | 用户 | 中低速率，允许短时突发 |
| 支付创建 | 用户 + 订单 | 低速率 |
| 领券 | 用户 + 券模板 | 低速率 |
| 商品查询 | IP | 较高速率，只保护异常流量 |

Redis 限流故障策略按接口分类：

- 浏览类接口可 fail-open，并记录降级。
- 登录、支付和管理类高风险接口默认 fail-closed 或使用受限本地兜底。
- 每项策略必须在配置与文档中明确，禁止隐式决定。

## 4. 审计数据

新增 `audit_logs`：

- 操作者 ID、角色和请求 ID。
- 操作类型、目标类型和目标 ID。
- 结果、来源 IP、时间和必要变更摘要。
- 失败原因分类。

规则：

- 价格、库存、状态等变更记录前后摘要。
- 密码、token、Cookie、支付签名和完整个人信息不得进入审计日志。
- 审计记录只追加，普通运营人员不能修改或删除。
- 审计写入失败对高风险管理操作采用明确策略并产生告警信号。

## 5. API 增量

管理员：

```text
GET /api/v1/admin/audit-logs
GET /api/v1/admin/security-events
```

支持按操作类型、操作者、目标、结果和时间范围分页查询。响应中的 IP 与用户敏感字段按权限脱敏。

## 6. 安全规则

- 只信任配置中的 Nginx 代理地址，不无条件信任所有代理头。
- refresh Cookie 使用 HttpOnly、合适的 SameSite 和生产 Secure 策略。
- 使用 Cookie 的状态变更接口验证 Origin/CSRF 策略。
- CORS 不允许凭据模式下的通配源。
- JSON、multipart 和 URL 参数设置明确大小上限。
- 错误响应不暴露 SQL、文件路径、密钥和调用栈。
- 用户输入用于日志时防止换行注入和无边界长度。
- 所有管理写操作经过认证、授权、校验、审计四层处理。

## 7. 实施步骤

1. 梳理接口风险并建立可配置限流策略表。
2. 实现 Lua 令牌桶和单元/Redis 集成测试。
3. 实现限流中间件、组合主体 key 和 429 响应。
4. 为 Redis 故障实现按风险分类的降级策略。
5. 创建审计表并定义审计事件模型。
6. 接入价格、库存、订单、退款和权限操作审计。
7. 收紧代理、CORS、Cookie、请求大小和安全响应头。
8. 对解析器和关键校验逻辑增加 fuzz test。
9. 执行权限、越权、重放、输入边界和日志泄露检查。

## 8. 测试要求

- 单实例和多实例并发请求遵守同一 Redis 限额。
- 不同用户/IP 的额度互不污染。
- Lua 脚本在并发下不出现负令牌或超发。
- Redis 故障时各类接口按预定 fail-open/fail-closed 行为执行。
- 伪造代理头不能绕过 IP 限流。
- 管理操作成功和失败均有合适审计记录。
- 审计与普通日志不包含敏感值。
- fuzz test 不触发 panic、无限分配或未处理异常。

## 9. 验收标准

- 高价值接口获得稳定、可配置的分布式限流保护。
- 超限响应包含 `429`、业务错误码和重试信息。
- 管理员可按条件查询关键操作历史。
- 已知越权、代理伪造、超大请求和日志泄露场景受到控制。
- 安全措施不改变正常业务结果。
- 全部自动化检查通过。

## 10. 本阶段不做

- 不自行实现加密算法或 WAF。
- 不进行 DDoS 清洗、验证码和设备指纹系统建设。
- 不把 Nginx 限流当成应用业务限流的替代品。

## 11. 阶段出口

应用已具备多实例共享的安全控制和审计能力，可以进入统一网关与容器化部署。
