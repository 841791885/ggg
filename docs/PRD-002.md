# PRD-002：分类、图片与迁移治理

## 1. 阶段信息

- 状态：部分完成（迁移治理 Goose、商品筛选分页、软删除已落地；分类和图片存储未实现，待补）
- 前置条件：PRD-001 验收通过
- 核心技术：MySQL 8、GORM、Goose、文件存储抽象、Testcontainers
- 阶段目标：在已有 MySQL 商品目录上补齐分类、图片、筛选和正式数据库迁移治理。

## 2. 功能范围

- 分类创建、修改、排序、启停和两级树查询。
- 商品关联一个叶子分类，支持修改分类。
- 完善 Product、SKU 和库存数据约束与索引。
- 商品列表按分类、状态、关键词和价格范围筛选。
- 商品图片上传、排序、删除和主图设置。
- 商品与 SKU 采用软删除，历史标识不复用。
- 数据库迁移、开发种子数据和就绪检查。
- 保持 PRD-001 的接口语义，必要变更必须记录兼容说明。

## 3. 技术决策

| 领域 | 选择 | 约束 |
| --- | --- | --- |
| 数据库 | MySQL 8 / InnoDB | 禁止使用不支持事务的存储引擎 |
| ORM | GORM + `go-sql-driver/mysql` | Repository 封装查询，业务层不依赖 GORM |
| SQL | GORM 为主，必要时使用参数化原生 SQL | 复杂查询必须理解实际生成的 SQL |
| 迁移 | Goose SQL migration | 所有结构变化必须有版本文件 |
| 测试 | Testcontainers MySQL | 集成测试不依赖开发者本机已有数据 |
| 图片存储 | `FileStorage` 接口 + 本地实现 | 数据库只保存文件标识和元数据 |

数据库统一配置：

- 字符集与排序规则使用 `utf8mb4` 对应配置。
- 数据库、应用会话统一使用 UTC，API 仍输出 RFC 3339。
- 启用严格 SQL 模式。
- DSN 必须启用时间解析，不在源码中硬编码密码。
- 设置最大连接数、空闲连接数、连接最大生命周期和查询超时。

## 4. 数据变化

新增或持久化以下表：

- `categories`：名称、父级、排序、状态、时间戳、软删除时间。
- `products`：名称、描述、分类、状态、时间戳、软删除时间。
- `skus`：商品、唯一编码、规格 JSON、价格、库存、状态、时间戳、软删除时间。
- `product_images`：商品、文件标识、访问路径、排序、是否主图、时间戳。

关键约束：

- SKU code 使用数据库唯一约束兜底。
- 价格与库存必须有非负/正数约束或等效写入保护。
- 外键字段建立索引。
- 商品名称关键词查询先使用 MySQL 基础能力，不提前接 Elasticsearch。
- 分类最多两级，存在启用商品或子分类时不能直接删除。
- 每个商品最多一张主图，切换主图使用事务。

## 5. API 增量

管理端新增：

```text
POST   /api/v1/admin/categories
GET    /api/v1/admin/categories
PATCH  /api/v1/admin/categories/:id
PUT    /api/v1/admin/categories/:id/status
DELETE /api/v1/admin/categories/:id
POST   /api/v1/admin/products/:id/images
PATCH  /api/v1/admin/products/:id/images/:image_id
DELETE /api/v1/admin/products/:id/images/:image_id
```

消费者端增强：

```text
GET /api/v1/categories
GET /api/v1/products?category_id=&keyword=&min_price_cent=&max_price_cent=&page=&page_size=
```

上传接口必须限制 MIME 类型、扩展名和大小；文件名由服务端生成，禁止直接使用客户端文件名作为磁盘路径。

## 6. 实施步骤

1. 增加配置加载与启动校验，建立数据库连接池。
2. 编写 Goose 初始化迁移和回滚迁移。
3. 扩展现有 GORM repository，并保持 service 契约。
4. 为 SQL 查询增加超时、错误转换和集成测试。
5. 实现分类模型、规则、接口和测试。
6. 扩展商品筛选、分页和排序查询。
7. 抽象并实现本地图片存储，完成文件安全校验。
8. 增加数据库就绪检查、开发种子数据和运行说明。
9. 验证从空数据库迁移、回滚及重新迁移。

## 7. 测试要求

- repository 集成测试必须使用真实 MySQL 8 行为。
- 测试唯一约束、外键、软删除、事务回滚和分页稳定性。
- 测试分类层级、循环父子关系和删除保护。
- 测试非法图片类型、超大文件和路径穿越输入。
- 测试连接超时或数据库不可用时返回受控错误。
- 保留 PRD-001 全部业务与 HTTP 回归测试。

## 8. 验收标准

- 服务重启后商品、SKU、分类和图片元数据不丢失。
- 空数据库可以通过一条迁移命令建立完整结构。
- 同一迁移不会被重复执行，回滚结果可解释。
- 数据库唯一约束能阻止并发重复 SKU code。
- 分类、关键词、价格筛选和分页结果正确且顺序稳定。
- 商品软删除后消费者不可见，关联记录仍可审计。
- 上传内容不能越过指定存储目录。
- `go test ./...`、`go test -race ./...` 和 `go vet ./...` 通过。

## 9. 本阶段不做

- 不实现登录、购物车和订单。
- 不引入 Redis、第二套 ORM、Elasticsearch、对象存储或 CDN。
- 不进行读写分离和分库分表。

## 10. 阶段出口

商品目录已具备分类、图片和正式迁移治理，服务层仍不依赖 GORM。验收通过后进入 PRD-003，为管理接口和消费者私有数据建立身份边界。
