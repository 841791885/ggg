# PRD-003：用户认证与角色权限

## 1. 阶段信息

- 状态：已完成（注册、登录、JWT、RBAC 权限点与角色隔离；刷新令牌吊销待补）
- 前置条件：PRD-002 验收通过
- 核心技术：bcrypt、JWT、Gin middleware、MySQL、CORS
- 阶段目标：建立安全的用户身份、令牌生命周期和消费者/运营/管理员权限边界。

## 2. 功能范围

- 用户名与邮箱注册，密码登录和退出。
- 短期 access token 与可轮换 refresh token。
- 查询、修改个人资料和修改密码。
- 消费者、运营人员、管理员三种角色。
- 管理员创建、停用和启用运营账号。
- 管理接口统一增加认证和角色校验。
- 登录失败次数限制和基础安全事件记录。
- 前后端分离所需 CORS 策略。

## 3. 技术决策

- 密码使用 bcrypt 哈希，数据库不保存明文或可逆密文。
- access token 使用 JWT，通过 `Authorization: Bearer` 传递，生命周期较短。
- refresh token 使用高熵随机值，浏览器端放入 HttpOnly Cookie；数据库只保存其哈希或唯一标识。
- refresh token 每次使用后轮换，旧 token 立即失效。
- JWT 只保存稳定、最小的身份声明，不放密码、个人资料或动态权限列表。
- 认证中间件解析身份，授权中间件校验角色；二者分开。
- 生产环境 Cookie 使用 `Secure`，CORS 只允许配置的可信前端源。

## 4. 数据变化

新增：

- `users`：用户名、邮箱、密码哈希、状态、角色、资料字段和时间戳。
- `refresh_tokens`：用户、token 哈希/JTI、过期时间、撤销时间、替换关系和客户端摘要。
- `security_events`：登录成功、失败、密码修改、令牌撤销和账号状态变化。

关键约束：

- 用户名和规范化邮箱分别唯一。
- 用户状态包含 `active`、`disabled`。
- 系统至少保留一个可用管理员。
- 禁止用户通过资料接口修改自己的角色或状态。

## 5. API 增量

公开接口：

```text
POST /api/v1/auth/register
POST /api/v1/auth/login
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
```

登录用户接口：

```text
GET   /api/v1/me
PATCH /api/v1/me
PUT   /api/v1/me/password
```

管理员接口：

```text
POST /api/v1/admin/operators
GET  /api/v1/admin/operators
PUT  /api/v1/admin/operators/:id/status
```

PRD-001/002 的 `/api/v1/admin/**` 接口从本阶段起只允许运营人员或管理员访问。

## 6. 核心规则

- 注册、登录失败统一返回不泄露账号存在性的消息。
- 修改密码需要验证旧密码，成功后撤销该用户全部 refresh token。
- 停用用户不能登录、刷新令牌或访问受保护接口。
- 普通消费者不能访问任一管理接口。
- 运营人员不能创建管理员或修改权限。
- 管理员不能停用系统中最后一个可用管理员。
- 服务端日志不能记录密码、完整 token、Cookie 或 Authorization 值。

## 7. 实施步骤

1. 建立用户、刷新令牌和安全事件迁移。
2. 实现用户 repository 和密码哈希服务。
3. 实现注册、登录与统一认证错误。
4. 实现 JWT 签发、校验和密钥配置。
5. 实现 refresh token 哈希保存、轮换和撤销。
6. 编写认证中间件，将当前用户放入请求 context。
7. 编写角色授权中间件并保护管理接口。
8. 实现个人资料、修改密码和运营账号管理。
9. 配置最小 CORS 白名单和 Cookie 策略。
10. 增加安全与越权测试。

## 8. 测试要求

- 密码哈希不可等于原始密码，错误密码无法通过。
- 重复用户名/邮箱注册在并发下只有一个成功。
- access token 过期、签名错误、声明缺失均被拒绝。
- refresh token 只能成功轮换一次，旧 token 重放被识别。
- 退出和修改密码后旧 refresh token 失效。
- 消费者、运营人员和管理员权限矩阵全部覆盖。
- 测试不同用户不能修改对方资料。
- 测试日志与响应不包含敏感凭据。

## 9. 验收标准

- 用户能完成注册、登录、刷新、退出和修改密码。
- 管理接口由角色正确保护。
- 停用账号的现有身份不能继续获得有效访问。
- 令牌重放与越权请求得到稳定错误响应。
- 密钥和初始管理员凭据不进入 Git。
- 自动化测试和竞态检查通过。

## 10. 本阶段不做

- 不接短信、邮件、OAuth 或第三方登录。
- 不实现任意配置型 RBAC，不提供权限管理 UI。
- 不把长期 refresh token 直接保存在 localStorage。

## 11. 阶段出口

系统已有可信的用户身份和角色边界。后续所有消费者私有资源必须绑定当前用户，不能接受客户端提交的 user ID 作为所有权依据。
