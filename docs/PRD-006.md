# PRD-006：Redis 缓存与购物车优化

## 1. 阶段信息

- 状态：预规划
- 前置条件：PRD-005 验收通过
- 核心技术：Redis、`go-redis/v9`、Cache Aside、TTL、singleflight
- 阶段目标：降低商品与购物车高频查询的数据库压力，并建立清晰的缓存一致性和故障降级策略。

## 2. 数据归属原则

- MySQL 继续是商品、购物车、订单和库存的事实来源。
- Redis 中的数据允许过期或丢失，必须能从 MySQL 重建。
- 订单创建始终重新读取 MySQL 的商品、价格和库存。
- 不允许因为 Redis 返回成功就跳过 MySQL 交易写入。

## 3. 功能范围

- 缓存消费者商品详情、分类树和热门商品列表。
- 购物车使用 MySQL 写入、Redis 缓存读取的 Cache Aside 模式。
- 商品、SKU 或分类更新后失效相关缓存。
- 为不存在商品短时缓存空结果，防止缓存穿透。
- 热点 key 过期时限制并发回源，防止缓存击穿。
- TTL 加入随机抖动，降低同时过期风险。
- Redis 不可用时回退 MySQL，并记录降级事件。
- 提供缓存命中、未命中、回源和错误的基础指标计数。

## 4. 技术设计

使用 `go-redis/v9`，所有调用携带 `context` 和明确超时。

key 必须有环境、应用、模块和版本前缀，例如：

```text
gomall:dev:catalog:v1:product:123
gomall:dev:catalog:v1:categories
gomall:dev:cart:v1:user:456
```

约束：

- 禁止使用 `KEYS` 扫描线上 key。
- JSON 缓存结构必须带版本边界，结构变化时可切换 key 版本。
- 写操作顺序采用“先提交 MySQL，再删除缓存”。
- 删除缓存失败需要记录并允许短期最终一致，不回滚已经成功的数据库事务。
- 商品详情正常 TTL、空值 TTL 和热门列表 TTL 分开配置。
- 单机阶段可用 `singleflight` 合并并发回源，多实例协调在 PRD-010 增强。

## 5. API 变化

业务 API 保持兼容，不要求前端感知缓存。

健康检查新增：

```text
GET /health/ready
```

就绪检查需要反映 MySQL 是否可用；Redis 是否影响就绪由降级策略决定。若 Redis 被定义为可降级依赖，其故障不能让整个商城永久不可用。

## 6. 核心规则

- 缓存只改变性能，不改变接口数据含义。
- 商品下架后必须先完成数据库状态变更，再使消费者缓存失效。
- 缓存中库存只用于展示，创建订单仍以 MySQL 事务校验为准。
- 购物车写入成功以 MySQL 提交为准，Redis 更新失败不向用户谎报数据库失败。
- Redis 错误分类记录，超时不能无限阻塞请求。
- 缓存对象不得包含密码、token 或不必要的用户敏感数据。

## 7. 实施步骤

1. 增加 Redis 配置、客户端、超时和关闭逻辑。
2. 设计 key 命名、TTL 和序列化版本。
3. 为商品详情实现 Cache Aside 和空值缓存。
4. 为分类树和热门商品列表增加缓存。
5. 在商品写操作后集中执行缓存失效。
6. 为购物车读取增加缓存，写入后失效或重建。
7. 使用 singleflight 合并同实例并发回源。
8. 实现 Redis 故障回退和降级日志/指标。
9. 增加缓存一致性与故障集成测试。

## 8. 测试要求

- 首次读取回源 MySQL，后续读取命中 Redis。
- 商品修改、上下架和 SKU 修改后不长期返回旧缓存。
- 不存在商品重复查询不会持续访问 MySQL。
- 同一热点 key 并发失效时回源次数受控。
- Redis 超时或关闭时商品、购物车查询按设计回退。
- 缓存中的伪造价格或库存不能影响订单创建。
- 不同用户的购物车 key 不串数据。

## 9. 验收标准

- 缓存命中能明显减少对应 MySQL 查询。
- 更新后数据在约定一致性窗口内正确。
- Redis 暂时不可用时核心商品浏览、购物车和下单不崩溃。
- 缓存故障可通过日志和计数定位。
- Redis 恢复后无需人工重建业务事实数据。
- 自动化测试与竞态检查通过。

## 10. 本阶段不做

- 不把订单、支付和最终库存存入 Redis 作为唯一来源。
- 不引入 Redis Cluster、哨兵或多级本地缓存。
- 不实现秒杀库存。

## 11. 阶段出口

系统具备可降级的缓存层。后续支付幂等仍主要依赖 MySQL 唯一约束，Redis 只可作为快速防重的辅助层。
